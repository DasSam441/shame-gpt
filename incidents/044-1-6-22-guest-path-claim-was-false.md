# 044 — CarreraMod 1.6.22 was incorrectly described as leaving Guest startup untouched

**What happened:** After 1.6.22 still crashed after Guest login, review found that TimTimeBootstrap called nativeInstallHooks() during Activity startup. The ARMv7 implementation installed five Dobby hooks immediately, before login. The earlier claim that the Guest path was free of native intervention was false.\n\n**Technical explanation:** Removing only the RunningState hook did not make startup passive: repeated bootstrap calls still reached native hook installation, where the remaining functional hooks were installed. The project note treats that as a plausible crash contributor, not a proven sole cause because no new tombstone established it.\n\n**Why this was my mistake:** I checked one hooks removal and generalized that into a claim about the whole startup path without tracing every bootstrap call to its native effects.\n\n**Evidence and limits:** docs/CARRERAMOD_1.6.22_ARMV7_GUEST_UNTOUCHED.md records the device crash, the discovered bootstrap calls, and explicitly retracts the prior claim. It does not prove those five hooks alone caused the crash.
