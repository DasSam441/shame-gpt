# 046 — CarreraMod 1.6.24 could silently miss installing the ARMv7 PLT guard

**What happened:** 1.6.24 remained blocked after a device crash. Source review found six fire-and-forget installation attempts at fixed delays; each discarded the native install result. If libil2cpp.so or its required APIs were not ready by the final attempt, no retry remained and the memset guard was never installed.\n\n**Technical explanation:** A delayed call is not a readiness guarantee. Fixed timers with ignored return values can all run before a shared library is available, leaving the critical patch absent while the application continues.\n\n**Why this was my mistake:** I relied on several scheduled attempts as if they ensured eventual installation, without checking whether any attempt succeeded or arranging a retry after the actual readiness condition.\n\n**Evidence and limits:** docs/CARRERAMOD_1.6.24_ARMV7_PLT_AND_DEFERRED_HOOKS.md documents the six times, discarded results, and required next change. It identifies a source-level failure mechanism; this report does not assert that it was the only cause of the device crash.
